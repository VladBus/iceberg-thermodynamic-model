# DECISIONS.md — журнал ключевых решений

Этот документ объясняет, почему текущая архитектура и физические схемы
выглядят именно так. Каждое решение подтверждается кодом, тестами и
отчётами; историческое обоснование — в `docs/wiki/`.

Формат: `ID | дата/стадия | статус` + краткое описание. Подробности — по
ссылкам.

---

## D-01. Реальная сетка реконструируется из IBCAO, а не из отсутствующих исторических файлов

- **Стадия:** 3.5 / 6.1 / 6.2 / 7.6A | **Статус:** ACTIVE (действует)
- **Проблема:** оригинальные `KOORD.DAT`/`hhh.bar` утрачены; поиск не дал результатов.
- **Решение:** сетка 133×105 (132×104 активных ячейки, DX=DY=13.89 км)
  реконструирована из IBCAO V5.2 (400 м, EPSG:3996); файлы генерируются
  скриптом `python/grid/build_real_grid_inputs.py` и симлинкаются в корень.
- **Почему:** единственный воспроизводимый источник батиметрии; `grid_mode=TEST` запрещён для производственных утверждений.
- **Источники:** `docs/wiki/stages/stage03/Stage3.5_real_grid.md`,
  `docs/wiki/stages/stage07/Stage7.6A_IBCAO_real_grid_reconstruction.md`.
- **Ограничения:** ячейки за пределами домена IBCAO покрыты ERA5 (5.2% сухих ячеек вне форсинг-домена).

## D-02. Смешанная система единиц: CGS-гидродинамика, SI-термодинамика

- **Стадия:** 6.4 / 5.5b | **Статус:** ACTIVE
- **Решение:** внутри модели: гидродинамика в CGS (см/с, дин/см²), термодинамика в SI (°C, массовая доля соли); конверсия только на границе NetCDF-вывода (`netcdf_output.f90`).
- **Почему:** наследие оригинальной модели Дмитриева–Нестерова; изменение внутренних единиц — отдельный рискованный этап.
- **Источники:** `docs/wiki/stages/stage06/Stage6.4_unit_audit.md`,
  `docs/wiki/stages/stage05/Stage5.5b_units.md`.

## D-03. Конвективный порог 0.9e-7 не повышается, EOS не переводится в double

- **Стадия:** 4.3 / 4.3b / 4.4 | **Статус:** ACTIVE
- **Проблема:** циклирование конвективной коррекции; корневая причина — float32-квантование `2⁻²³ ≈ 1.19e-7` против порога 0.9e-7.
- **Решение:** порог и точность не менять; мониторинг через `ca_reset`/`ca_stats`; 1000-итерационный guard. Изменение требует отдельной процедуры (promt.md) и одобрения.
- **Источники:** `docs/wiki/stages/stage04/Stage4.3_convective_root_cause.md`,
  `docs/wiki/stages/stage04/Stage4.4_precision_study.md`.

## D-04. FCT-антидиффузия намеренно отключена

- **Стадия:** ранняя | **Статус:** ACTIVE
- **Решение:** `CDY*0` в `barotropic_dynamics.f90` (X-блок промежуточных величин обнулён).
- **Почему:** «исправление» вызывает взрыв (blowup).
- **Источники:** комментарии в коде; `AGENTS.md` (Constraints).

## D-05. Точка замерзания океана — EOS-80/UNESCO (замена линейного закона Зубова)

- **Стадия:** 10.5 | **Статус:** ACTIVE
- **Решение:** `Tf(S,p) = (A0 + A1√S − A2·S)·S + BP·P` (Fofonoff & Millard 1983); литературный checkvalue Tf(40 PSU, 500 dbar) = −2.588567 °C воспроизведён.
- **Почему:** давление-зависимая формула физически корректна на глубине киля; старый закон Зубова давал спуриозное таяние ниже ~8 м.
- **Источники:** `docs/validation/stage10.5` → `docs/wiki/stages/stage10/Stage10.5_Ocean_Thermal_Forcing.md`,
  `docs/model/model_equation_ledger.md` §4.5–4.7.

## D-06. Трёхкомпонентный интерфейс лёд–океан с массово-солевой коррекцией

- **Стадия:** 10.10 / 10.10.1 | **Статус:** ACTIVE (selectable, bulk-путь не тронут)
- **Решение:** схема H&J99/J2010 (`solve_three_equation_interface`); Eq. III в масс-сохраняющей форме `ρ_w γ_S (S_w − S_B) = ρ_i m S_B` (конвенция MOM6/PISM/MITgcm/H&J99 Eq. 4), НЕ `γ_S (S_w − S_B) = m S_B` (подразумевало ρ_i/ρ_w = 1).
- **Эффект:** канонический якорь H&J99 m увеличился на 10.5%; производственный end-to-end m на 1.7%.
- **Источники:** `docs/validation/stage10.10_three_equation_interface.md`.

## D-07. Естественная конвекция: формулировка сохранена, несмотря на выявленные ограничения

- **Стадия:** 10.11 / 10.11.2 / 10.11.3 | **Статус:** ACTIVE (selectable), ограничения задокументированы
- **Проблема:** Ra-кап 1e10 всегда активен (Nu закреплён на 323.17); haline-член инертен; знак haline-члена противоположен физической стабилизирующей роли; нулевой поток 1.4e-3 m/day на 7–700× ниже наблюдательной полосы 0.01–1 m/day.
- **Решение (10.11.3):** производство НЕ менять (нет лучшей альтернативы без новых данных); механизм признан кап-определённым; реальный механизм — двойная диффузия (MK77/Keitzl16/Middleton21) → мотивация Stage 10.13.
- **Источники:** `docs/validation/stage10.11.3_natural_convection_physics_audit.md`.

## D-08. Прогностическая внутренняя температура — двухузловая модель, полностью гейтованная

- **Стадия:** 10.12 | **Статус:** ACTIVE
- **Решение:** `T_ice` (два узла: поверхность + интерьер), явный Эйлер, кламп [−100, 0]°C; switch `thermal_evolution_enabled` (default ON) **полностью** отключает стадию в шаге: OFF = бит-в-бит legacy (проверено F.1–F.4).
- **Почему:** константа `T_i = −10` была модельным допущением; двухузловая модель — минимум, дающий энергетически согласованный отклик без внутренней сетки.
- **Ограничения:** lumped (Bi ≫ 1); избыточная энергия при клампе отбрасывается; `K_ICE` не калиброван.
- **Источники:** `docs/validation/stage10.12_internal_thermal_evolution.md`, дизайн-нота рядом.

## D-09. Low-flow закрытие — исследовательская параметризация за переключателем OFF по умолчанию

- **Стадия:** 10.13 (Phases A–C) | **Статус:** ACTIVE (research parameterization)
- **Решение:** гибрид «диффузионно-ограниченный подслой + double-diffusive усиление» интегрирован в производство через `low_flow_closure_enabled` (OFF по умолчанию); смешиваются эффективные γ_T/γ_S перед существующим 3eq-солвером (не m); legacy-страж `u_rel ≤ 0 → m=0` сохранён через `allow_zero_flow`; NaN-fallback на форсированную ветку.
- **Почему:** закрывает наблюдательный разрыв нулевого потока (0.107 m/day при U=0 против 1.4e-3), не трогая форсированную ветку (бит-в-бит при высоком U).
- **Ограничения:** t_scale = 1 сут (доминирующая чувствительность), f_dc = 2.5 не калиброван, κ_S-конвенция (Le=100) на 4.4% отличается от Python-референса.
- **Источники:** `docs/validation/stage10.13_phase_c_results.md`, `docs/validation/stage10.13_phase_b_results.md`, дизайн-нота.

## D-10. Скалярная калибровка коэффициента базального таяния НЕ проводится

- **Стадия:** 10.9 | **Статус:** ACTIVE
- **Решение:** требуемый C_γ различается на 0.918 порядка между двумя независимыми источниками (NJ80, KW84); расхождение функциональной формы (obs ~ dT^1.73 против закрытия dT^1.0) не поглощается скаляром. Калибровка отложена до трёхкомпонентного закрытия (10.10+) и re-scoring 10.8.2.
- **Источники:** `docs/validation/stage10.9_calibration_assessment.md`.

## D-11. Переключатели сохраняют legacy-поведение при OFF

- **Стадия:** 10.10–10.13 | **Статус:** ACTIVE (обязательное требование)
- **Решение:** каждая новая физика входит за runtime-переключателем; OFF обязан давать бит-в-бит прежний результат (проверяется тестами legacy-инвариантности: 10.12 F.1–F.4, 10.13 A.1/D.1).
- **Почему:** минимизация риска регрессий и воспроизводимость старых прогонов.

## D-12. Удалена неиспользуемая зависимость stdlib из fpm.toml

- **Стадия:** 10.12 | **Статус:** DONE
- **Проблема:** `fpm build` компилирует только цели, достижимые из targets; stdlib (0 `use stdlib*` в репозитории) ломал частичный клон и сетевую сборку fpm 0.13.0-alpha.
- **Решение:** зависимость удалена; чистка `build/` обязательна перед `fpm test`.

## D-13. Инициализация реального льда: OSI-SAF SIC + C3S CS2SMOS SIT

- **Стадия:** 7.6C.1 | **Статус:** ACTIVE
- **Решение:** концентрация/толщина на 2020-01-01 реконструируются на влажной маске модели в две корзины с сохранением площади/объёма → категорийные файлы `1_1.ice`–`1_5.ice`.
- **Источники:** `docs/wiki/stages/stage07/Stage7.6C.1_Real_ice_initialization.md`.

## D-14. Инициализация океана EN4: thermal-wind коррекция и спин-ап вместо сырого EN4

- **Стадия:** 7.7–7.9, 8.0–8.6 | **Статус:** ACTIVE
- **Проблема:** сырое EN4-поле динамически несовместимо с нулевой начальной скоростью (Stage 7.7B: blowup на 2-й день, классификация C).
- **Решение:** последовательность thermal-wind коррекции, дискретного steady-state решения и контролируемого спин-апа (Stages 8.2–8.6).
- **Источники:** `docs/wiki/stages/stage07/Stage7.7B_Realistic_Ocean_Stabilization.md`,
  `docs/wiki/stages/stage08/` (8.2–8.6).

## Как добавлять решения

Новое решение добавляется в конец таблицы с ID, стадией, статусом и
ссылками на отчёты. Решение должно подтверждаться кодом/тестами/историей;
не добавляются непроверенные предположения.
