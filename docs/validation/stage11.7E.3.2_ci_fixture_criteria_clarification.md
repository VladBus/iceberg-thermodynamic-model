## 3. Phase 2 — 11.7E.4 criteria clarified (A/B/C)

The previous acceptance text — `env-gated switch (default OFF → bit-identical;
ON ≡ OFF)` — demanded both that the switch be a no-op and that real data be
connected. Replaced in `docs/PROJECT_ROADMAP.md` with:

- **A. Baseline reproduction (switch OFF):** default OFF → diagnostic-zero
  path reproduces the legacy baseline bit-identically (reader not invoked).
- **B. Reader equivalence (NetCDF vs Legacy, same real source):** with the
  switch ON, the NetCDF reader reproduces the legacy `1_*.ice` reader given
  the SAME real source data (X ≡ Y within documented tolerance; no physics
  change).
- **C. Scientific migration (real data connection):** connecting the real
  OSI-SAF SIC + C3S SIT product is a scientific change relative to the
  diagnostic-zero baseline; document expected differences and validate — do
  NOT require identity with the baseline.

The distinction prevents the 11.7E.4 implementer from either (a) claiming
success with a no-op switch, or (b) failing a legitimate scientific result
for not being bit-identical to zeros.

## 5. Phase 4 — Snowfall conversion protection

`merge_snowfall.py` converts 12-hour accumulations to rates with
`snow_accum / 43200.0` and linearly interpolates 12-hourly → 6-hourly. The
contract test now protects this with five checks:

1. `merge_snowfall.py` contains the `43200` factor.
2. Accumulation period is 12 h (43200 s) — raw `valid_time` diff, or fixture
   metadata.
3. Accumulation units are `m of water equivalent`.
4. Merged rate equals raw accumulation / 43200 (real mode) or the fixture's
   known accumulation / 43200 (fixture mode).
5. Non-zero snowfall cells are present (≥ 1000 in real mode; exact 200 in
   fixture mode).

Verified raw facts (April 2020): raw `sf` shape (60,101,1440), units
`m of water equivalent`, max 0.005072116851806641, `valid_time` units
`seconds since 1970-01-01`, diff 43200 s (12 h); merged `sf` max
1.1741011e-7 m/s, 15,053,341 non-zero cells.

Both test modes execute five conversion checks (real mode uses the raw file;
fixture mode uses the fixture metadata).
